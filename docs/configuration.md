# 完整设置说明

本页与当前代码中的字段一致。面板中修改监控和 SMTP 会保存到 SQLite；`.env` 用于 Docker Compose 启动参数。二者用途不同。

## 监控总览与状态

| 状态     | 含义                                       | 是否会触发邮件                   |
| -------- | ------------------------------------------ | -------------------------------- |
| 已暂停   | 该机型的“启用监控”未勾选                   | 不检查、不产生新补货通知         |
| 未知     | 未检测、验证页、规则不匹配或证据不足       | 不触发                           |
| 检测失败 | 非 200 HTTP 响应、网络错误或超时           | 不触发，后续自动重试             |
| 确认中   | 当前已读到明确库存，但尚未满足连续确认次数 | 等确认完成后再决定               |
| 有货     | 当前有货结果与已确认状态一致               | 仅符合所设通知策略的状态转换触发 |
| 缺货     | 当前缺货结果与已确认状态一致               | 只记录状态，不发补货邮件         |

“今日检查”和健康度统计的是滚动最近 24 小时，不是从北京时间零点开始。健康度为成功识别有货或缺货的检查次数 / 全部检查次数。所有时间在面板按北京时间显示。

“刷新状态”只重新取得后台数据，不立即访问商家。“检查”将已启用的机型加入检查队列，同站点仍遵守调度间隔。刚完成检测的 10 秒内不能再次手动要求检查。

## 监控基本字段

| 面板字段     | JSON 字段       | 默认值 / 限制                | 如何填写                                                       |
| ------------ | --------------- | ---------------------------- | -------------------------------------------------------------- |
| 商家         | `provider`      | 必填，1–80 字符              | 如 `VMISS`；也可输入自定义商家，用于筛选和展示                 |
| 机型名称     | `name`          | 必填，1–160 字符             | 你的监控名称；实际识别还依赖下面的检测规则                     |
| 检测地址     | `url`           | 启用时必填                   | 产品页、WHMCS 目录或公开 JSON 接口的完整 URL                   |
| 购买地址     | `purchase_url`  | 可空                         | 邮件及“商品页”按钮的目标地址；留空使用检测地址                 |
| 检测方式     | `adapter`       | `html`                       | HTML、WHMCS 或 JSON，见下节                                    |
| 检查间隔     | `interval`      | 120 秒；30–86400 秒          | 常规建议 120 秒；机型较多时实际执行会排队                      |
| 连续确认次数 | `confirmations` | 2；范围 1–5                  | 有货、缺货都需要连续达到次数；1 次最快，但更容易受页面瞬态影响 |
| 机房 / 地区  | `region`        | `Los Angeles`；最多 100 字符 | 展示备注，不自动检查线路和机房                                 |
| 配置详情     | `specs`         | 可空，最多 800 字符          | CPU、内存、硬盘、流量等说明                                    |
| 价格参考     | `price_note`    | 可空，最多 160 字符          | 明确币种和付款周期，如 `5 CAD/月`；不参与库存判断或价格过滤    |
| 备注         | `notes`         | 可空，最多 1500 字符         | 线路、优惠限制、来源、需要核实的问题                           |

检测和购买地址只允许 HTTP / HTTPS，端口为 80 / 443，最多 2048 字符，不能嵌入用户名、密码。抓取时还会拒绝本机、内网、云元数据、多播和保留地址。跨域跳转需人工核实并改填新地址；HTTPS 不允许降级到 HTTP。

## 三种检测规则

### HTML：定位唯一产品区域

适用于服务器直接返回产品库存文字的页面。

| 面板字段            | JSON 字段       | 说明                                                                     |
| ------------------- | --------------- | ------------------------------------------------------------------------ |
| 产品区域 CSS 选择器 | `selector`      | 启用 HTML 检测时必填，最多 300 字符。例如 `.product`、`tr`、`#product32` |
| 区域中包含的产品名  | `product_match` | 在选择器结果中进一步按包含文字筛选，最多 160 字符；留空则不额外筛选      |
| 预期产品文字        | `expected_text` | 可选，最多 160 字符；最终区域必须含有它，防止产品变更                    |
| 有货标记            | `in_stock`      | 每行一个；默认 `In Stock`、`有货`                                        |
| 缺货标记            | `out_of_stock`  | 每行一个；默认 `Out of Stock`、`Sold Out`、`缺货`、`售罄`                |

选择器加产品名筛选后，必须只剩一个区域。0 个或多个都返回未知。文字匹配忽略大小写并合并空白；每组标记必须有 1–20 项，每项 1–200 字符；两组不能出现相同标记。缺货标记优先于有货标记。

例如，VMRack：

```text
检测地址：https://www.vmrack.net/pricing
CSS 选择器：tr
产品名筛选：L3.VPS.DC2.2C2G.Base
预期产品文字：L3.VPS.DC2.2C2G.Base
有货标记：Buy now
缺货标记：Sold Out
```

如同一行同时出现 `Sold Out` 和 `Buy now`，结果是缺货。不要用整页的通用“购买”按钮判断某一款机器。脚本和显式隐藏节点被剔除，但程序不运行 CSS/JavaScript 渲染；动态页面应寻找公开接口或更精确的区域。

### WHMCS：确认具体商品

检测地址可以是包含真实 `pid` 的商品链接：

```text
https://商家域名/cart.php?a=add&pid=实际产品编号
```

“预期产品文字”必填，使用商品正式名称。仅出现 Order Now 不算有货；页面需包含预期产品文字及 `#frmConfigureProduct` 产品配置表单。明确缺货优先；登录、人机验证、PID 改变或丢失都不能判为有货。

也可使用 WHMCS 产品目录地址。“预期产品文字”必须和 `.product` 卡片里的产品标题精确一致。程序读取唯一卡片、提取 PID，再等待 5 秒访问对应配置页。目录需要客户端渲染或模板不同，可能无法自动读取，此时填写直接商品链接。

WHMCS 模式不使用 HTML 的选择器 / 产品名筛选，也不使用“有货标记”；“缺货标记”仍参与判断。面板当前仍显示标记输入框，保留有效默认值即可。

“从 WHMCS 目录读取机型”只提取公开目录中的名称、PID、链接及部分描述；读取后可选择添加，不会自动下单或一次性启用所有产品。每分钟最多读取 4 次。

### JSON：匹配精确库存值

“JSON 字段路径”即 `json_path`，启用时必填，最多 200 字符。使用点分对象键或数组索引，如 `data.products.0.available`。

假设接口返回：

```json
{ "data": { "products": [{ "available": true }] } }
```

则填写：

```text
JSON 字段路径：data.products.0.available
有货标记：true
缺货标记：false
```

此模式要求完整值匹配，不是包含匹配。数字可填 `1` / `0`，字符串按接口实际取值填写；对象或数组不能直接作为库存值。路径不存在、JSON 无效、未匹配任何值都返回未知。当前不支持大于零等表达式、JSONPath 查询语法或自定义请求认证。

### 试运行规则

保存前可“试运行规则”，只做一次读取并返回状态、原因和耗时；不累计连续确认，不存入检测历史，也不发送邮件。每分钟最多 6 次。没有填检测地址时不能试运行。

## 单机型通知开关

| 开关               | JSON 字段        | 默认 | 效果                                                                 |
| ------------------ | ---------------- | ---- | -------------------------------------------------------------------- |
| 启用监控           | `enabled`        | 关闭 | 是否后台检查；需要先补齐规则                                         |
| 补货时发送邮件     | `notify`         | 开启 | 该机型是否允许生成补货邮件，还需全局 SMTP 开关开启                   |
| 首次确认有货也通知 | `notify_initial` | 关闭 | 开启后，未知基线第一次确认有货也提醒；关闭时只通知已确认缺货后的补货 |

默认策略示例：第一次检测有货不会提醒；连续确认缺货后，再连续确认有货才提醒。希望启动后发现现货也收到提醒，需要同时打开“首次确认有货也通知”。

修改检测地址、方式、选择器、产品匹配、预期文字、JSON 路径、库存标记、确认次数，或切换启停，会清空该监控基线并取消旧规则的排队通知。修改名称、备注、价格等展示字段不重置库存基线。

## 全局邮件与账号设置

完整 SMTP 字段、测试及错误处理见 [邮件配置总说明](email/README.md)，具体服务商见 [QQ](email/qq.md)、[Gmail](email/gmail.md)、[163](email/163.md)。邮件配置与机型规则保存在数据库，修改保存即可生效，无需重启。

“邮件通知”可新增、编辑、删除最多 20 组配置，一次选用一组发信。升级后已有 SMTP 配置自动显示为“默认邮箱”，原授权码保留；备份和管理员密码位于独立的“系统设置”。

管理员密码在面板“系统设置”修改，需要当前密码，新密码至少 12 字符。修改后所有登录会话失效，旧的初始密码文件被删除。会话最长保留 24 小时。

首次创建数据库时读取 `ADMIN_PASSWORD`；没有设置则随机生成，写入数据目录 `initial-password.txt`。之后修改 `.env` 不会重置已有管理员密码。

## 镜像源（多源轮询）

入口：**系统设置 → 镜像源**，一个开关控制是否启用。

当商家官网被 Cloudflare 人机验证拦截（返回 403 + `cf-mitigated: challenge`）时，程序会改用公开的 VPS 聚合站（VPS 值得买、HostMonit）作为备用数据源，读取同一机型的补货状态。仅对 `whmcs` 检测方式生效。

- **限频**：每个聚合站默认每 10 分钟最多请求一次，多个监控项共享同一缓存，不会重复打站。
- **轮换**：多个聚合站按顺序轮换刷新，分散请求压力。
- **匹配**：只在产品名附近的小范围文本内匹配有货/缺货标记，避免把页面其他位置的“有货”误判到当前机型。
- **关闭后**：仅使用商家官网检测，Cloudflare 拦截时显示错误，不访问聚合站。

镜像源列表定义在 `app/mirror_sources.json`，可自行增删；新增源需确认其页面包含商家名与产品名。镜像结果会标注“聚合站 …（官网 Cloudflare 拦截备用源）”，与官网直连结果区分。

## 导入导出

入口：**系统设置 → 监控配置备份**。

- 导出文件含 `version` 和 `monitors`，只包含监控配置；不包含 SMTP 密码、管理员密码、会话及历史。
- 导入接受相同结构；每次最多 100 条、请求大小最多 128 KB。单实例累计最多 500 个监控。
- 导入的机型全部暂停，需要核对后开启。任一条配置无效则整批拒绝，不产生半成功导入。
- 新增 / 导入遇到同商家、同名称、同 URL 时跳过重复项。编辑已有记录不依赖这一去重判断。
- 删除监控会删除其检测历史；库存事件和通知记录按保留期保留。

导出是规则备份；需要恢复 SMTP、密码和历史时，要备份整个数据库和密钥，见 [备份与恢复](deployment.md#备份与恢复)。

## 运行环境变量

| 变量             | 默认 / 来源                      | 配置位置与作用                                                                 |
| ---------------- | -------------------------------- | ------------------------------------------------------------------------------ |
| `ADMIN_PASSWORD` | 本地未设置时生成；Compose 必填   | 仅首次初始化有效；至少 12 字符，不能使用 `.env.example` 的占位值               |
| `BIND_ADDRESS`   | `127.0.0.1`                      | Compose 宿主机监听地址；使用现有反向代理或 SSH 隧道通常保持默认                |
| `PORT`           | `8080`                           | Compose 宿主机映射端口；容器内部仍是 8080                                      |
| `DOMAIN`         | 空                               | Caddy 的域名，不带协议、路径、端口；使用 HTTPS profile 时需要设置              |
| `APP_ORIGIN`     | 空，按请求计算                   | 浏览器实际访问的来源，如 `https://radar.example.com`；用于写请求来源校验       |
| `SECURE_COOKIES` | `false`                          | HTTPS 部署设置 `true`；直接 HTTP 保持 `false`，否则浏览器可能不发送登录 Cookie |
| `DATA_DIR`       | 本地 `data`；容器 `/data`        | 数据库、密钥、初始密码所在目录；Compose 中固定为 `/data` 并挂载命名卷          |
| `HOST`           | 本地 `127.0.0.1`；镜像 `0.0.0.0` | `python -m app` 的监听地址；与 Compose 的宿主机映射地址不同                    |

`.env` 被 Docker Compose 读取，原生 Python 不自动读取 `.env`。`DATA_DIR` 和 `HOST` 当前没有通过 Compose 的 `${...}` 变量映射，因此仅在 `.env` 里添加它们不会改变容器的默认目录或内部监听。

原生运行设置变量示例：

```powershell
# Windows PowerShell；示例不包含密码，首次启动读取生成的密码文件
$env:DATA_DIR = 'E:\我的git项目\Github\vps-monitor\data'
.venv/Scripts/python.exe -m app
```

```bash
# Linux；在仓库根目录执行
DATA_DIR=./data .venv/bin/python -m app
```

原生 `python -m app` 固定使用 8080；需要改端口时：

```bash
python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 18080 --no-proxy-headers
```

HTTPS 配置例子：

```dotenv
DOMAIN=radar.example.com
APP_ORIGIN=https://radar.example.com
SECURE_COOKIES=true
BIND_ADDRESS=127.0.0.1
PORT=8080
```

这段仅说明网络参数，还需在自己的 `.env` 中保留实际 `ADMIN_PASSWORD`。然后使用 `docker compose --profile https up -d --build --wait`。

## 固定的运行策略

当前没有面板入口修改以下参数：

| 项目                | 实际行为                                                                                                                            |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 面板刷新            | 每 15 秒；隐藏标签页时暂停轮询，恢复可见时刷新                                                                                      |
| 调度检查            | 约每秒扫描到期任务，最多 4 个并发，同站点只允许一个检查                                                                             |
| 同站点间隔          | 完成一次检查后至少等待 5 秒                                                                                                         |
| 异常退避            | `min(检查间隔 × 2^min(连续异常次数, 5), 3600)` 秒，再加最多 10 秒抖动；因此配置间隔大于 1 小时的机型遇到异常时也按最多约 1 小时重试 |
| 正常检查            | 恢复配置的间隔，额外增加最多 10 秒抖动                                                                                              |
| 检查保留            | 7 天，且最多 20 万条                                                                                                                |
| 库存事件 / 通知保留 | 90 天                                                                                                                               |
| 邮件重试            | 最多 5 次尝试；失败后的重试间隔约 1、2、4、8 分钟                                                                                   |
| 补货邮件有效期      | 尚未发送的补货事件超过 1 小时会取消；测试邮件不受补货过期规则限制                                                                   |
| 密钥文件            | `DATA_DIR/secret.key`；SMTP 加密数据须使用同一密钥解密                                                                              |
| 实例数量            | 一个数据目录一个进程、一个 Uvicorn worker                                                                                           |

修改代码中的运行策略后需重启服务；修改面板规则则不需要。

## 商家访问受限与预设地址

VMISS TRI 目录在本次核查中返回 HTTP 403，响应头 `cf-mitigated: challenge`，页面标题为 `Just a moment...`。更换为浏览器 User-Agent 仍被验证拦截。面板会提示 Cloudflare 验证；这不是库存结果，修改产品匹配规则也不能完成浏览器验证。需要商家提供允许自动监控的公开接口，或放行部署服务器的访问。电脑浏览器可以访问不代表服务器可访问。

DMIT 三个预设已补充不含推广参数的候选商品入口：

| 预设 | 检测 / 购买入口 |
| --- | --- |
| LAX.Pro.WEE | https://www.dmit.io/cart.php?a=add&pid=183 |
| LAX.EB.CORONA | https://www.dmit.io/cart.php?a=add&pid=218 |
| LAX.AS3.Pro.TINY | https://www.dmit.io/cart.php?a=add&pid=253 |

这些入口本次也返回验证页，尚未在实际商品页确认身份和库存。预设仍默认暂停，启用前核对产品名并试运行；不要将相似名称的其他线路套餐当作替代。已有监控配置不会被新版预设覆盖，可编辑原监控填入地址，或从新版预设重新添加。
