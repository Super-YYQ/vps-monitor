# 邮件通知配置总说明

[返回 README](../../README.md) · [完整设置说明](../configuration.md)

VPS Radar 使用你提供的邮箱账户发送通知。配置的是“发信邮箱”，收信邮箱可以和它相同，也可以不同。SMTP 只负责发信，程序不读取收件箱。

## 选择发件邮箱

| 邮箱              | 详细指南               | SMTP 服务器      | 端口 / 加密                  | 所需凭据            |
| ----------------- | ---------------------- | ---------------- | ---------------------------- | ------------------- |
| QQ 个人邮箱       | [QQ 配置](qq.md)       | `smtp.qq.com`    | 465 / SSL                    | QQ 邮箱授权码       |
| Gmail             | [Gmail 配置](gmail.md) | `smtp.gmail.com` | 465 / SSL，或 587 / STARTTLS | Google 应用专用密码 |
| 网易 163 个人邮箱 | [163 配置](163.md)     | `smtp.163.com`   | 465 / SSL                    | 网易邮箱授权码      |

上表对应的官方资料与核对日期见各指南。企业邮箱、学校邮箱、VIP 邮箱可能使用不同服务器或限制，按所属服务商配置。

## 面板各项是什么

路径：**邮件通知 → 新增邮件配置**，或点击已有卡片的“编辑”。

最多保存 20 组配置，一次选用一组发信。第一组自动设为当前，后续新增的配置作为备用，可点“设为当前”切换。已有单组 SMTP 配置升级后保留为“默认邮箱”，无需重填授权码。删除当前配置后邮件通知停用，需另选一组。

| 设置项             | 含义                     | 填写要点                                                         |
| ------------------ | ------------------------ | ---------------------------------------------------------------- |
| 配置名称 | 卡片中显示的名称 | 例如“QQ 主邮箱”或“Gmail 备用”，最多 80 字符 |
| 选用此配置时启用通知 | 当前配置的发信开关 | 只有选为当前且开启此开关，后台才处理邮件；单机型也需允许通知 |
| SMTP 服务器        | 邮箱服务商的发信服务器   | 如 `smtp.qq.com`；不要加 `https://`、端口或路径；最多 253 字符   |
| 端口               | 连接 SMTP 服务的端口号   | 1–65535；使用服务商给出的端口，QQ/163 示例为 465                 |
| 加密方式           | 发信连接的加密协议       | SSL / TLS 通常配 465；STARTTLS 通常配 587；当前不支持明文发信    |
| 登录账号           | 用哪个账户进行 SMTP 认证 | 三份指南都填完整发件邮箱地址，最多 254 字符                      |
| 密码 / 邮箱授权码  | 程序使用的发信凭据       | QQ/163 填授权码，Gmail 填应用专用密码；最多 500 字符             |
| 发件人邮箱         | 邮件的 From 地址         | 初次配置与登录账号相同；只填邮箱地址，不填“名称 <邮箱>”          |
| 接收邮箱           | 谁收到补货提醒           | 每行一个完整地址，最多 20 个；可以填写自己或其他已获同意的接收者 |

首次保存前应完成所有字段。保存后授权码不会回显；再次保存时密码框留空只保留本组原授权码，新增配置不会借用其他组的授权码。更换发信账户时，应同时更新服务器、登录账号、授权码和发件人，避免沿用旧账户授权码。

凭据加密存入数据库，密钥保存在 `data/secret.key`（容器内为 `/data/secret.key`）。不要将 `.env`、数据库、密钥或备份上传到 GitHub。

## 保存与测试

1. 在所选邮箱的网站开启 SMTP，并获取授权码或应用专用密码。
2. 在面板新增配置，填写名称和 SMTP 参数，勾选“选用此配置时启用通知”。
3. 点击 **保存配置**，再在卡片中 **设为当前**（第一组自动选中）。测试按钮使用已保存的当前配置。
4. 点击当前卡片的 **发送测试邮件**。这会实际向已保存的所有收件人发信。
5. 打开 **通知记录**，等待投递结果；同时检查收件箱、垃圾邮件和规则分流文件夹。

测试邮件标题为 `[VPS Radar] 邮件通知测试`。每 5 分钟最多提交 3 次测试，避免反复触发邮箱风控。

## 通知记录怎么看

| 状态            | 含义                                           | 下一步                                                 |
| --------------- | ---------------------------------------------- | ------------------------------------------------------ |
| 待发送 / 重试中 | 已入队或上次发送失败后等待重试                 | 确认后台运行、SMTP 开关开启；查看错误说明              |
| 已发送          | 邮箱服务器已接受邮件                           | 最终入箱还可能被过滤；检查垃圾邮件或收件规则           |
| 发送失败        | 已达到 5 次尝试上限                            | 修复配置后重新提交测试；旧失败记录不会自动恢复为待发送 |
| 已取消          | 补货通知过期、库存改变、机型停用或检测规则改变 | 查看机型最新状态，需要时再启用监控                     |

仅开启全局邮件不会立刻发送所有当前有货机型。请同时检查每个机型的“启用监控”“补货时发送邮件”和“首次确认有货也通知”。SMTP 未启用时已发生的旧事件，不会在之后开启邮件时自动补发。

关闭当前配置的通知开关会暂停队列处理，不直接删除待发送记录；重新开启时仍会检查补货通知是否过期。库存通知默认超过 1 小时取消，测试邮件无这一补货时效限制。

切换当前配置后，尚未开始发送的补货通知使用新配置；未发送的测试邮件会取消，需重新测试。已开始的 SMTP 投递可能仍由原配置完成。每组授权码独立加密保存。

## 常见问题

| 现象                               | 优先检查                                                                             |
| ---------------------------------- | ------------------------------------------------------------------------------------ |
| SMTP 认证失败                      | 是否填写完整邮箱；是否用授权码 / 应用专用密码；是否已撤销或更换；SMTP 服务是否已开启 |
| SMTP 连接超时                      | 运行程序的 VPS 是否能访问该主机和端口；云厂商出站规则、系统防火墙、DNS 和网络线路    |
| SSL / TLS 失败                     | 465 是否选择 SSL；587 是否选择 STARTTLS；服务器时间和 CA 证书是否正常                |
| 邮件服务器拒绝发信                 | 登录邮箱与发件人是否一致；账户是否限制外部应用、发信频率或收件人                     |
| 已发送但没收到                     | 垃圾邮件、收件人拼写、邮箱过滤规则；“已发送”表示 SMTP 接受，不保证出现在主收件箱     |
| 测试成功，但补货不通知             | 机型通知开关、连续确认次数、首次有货开关、实际库存是否发生确认转换                   |
| 修改输入框后测试仍使用旧值         | 先点击保存，再发送测试邮件                                                           |
| Gmail 连接失败，但电脑能打开 Gmail | SMTP 连接从部署服务器发起，电脑网页可访问不代表服务器 SMTP 端口可达                  |

可以在 Windows 上测试 TCP 连通性：

```powershell
Test-NetConnection smtp.qq.com -Port 465
# 按指南替换主机；必须在实际运行服务的主机上检查
```

Linux 服务器可以使用：

```bash
openssl s_client -connect smtp.gmail.com:465 -servername smtp.gmail.com -brief </dev/null
```

这些命令只检查网络 / TLS，不会验证授权码，也不会发送邮件。不要把授权码作为命令行参数写入 shell 历史。

## 投递保证

同一已确认补货事件最多创建一条通知记录，队列和库存基线重启后保留。但是 SMTP 已接受邮件、程序尚未更新数据库时中断，或部分收件人被拒绝后重试，可能造成重复收到邮件。此工具不承诺跨 SMTP 的严格只投递一次。
